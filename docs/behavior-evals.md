# Skill 行为验收案例

以下是供维护者在实际 Agent 环境中复测的案例，不是已完成的端到端模型评测成绩。静态审阅只能确认指令覆盖；最终需要观察安装后的模型行为。

| 输入 | 应触发/行为 | 不应出现 |
| --- | --- | --- |
| 帮我做一个虚构老将的告别游戏，没想好风格 | 触发；少量首轮问题，提出具体体验方向 | 一次发出 58 题；直接认定水墨五章 |
| 做一款中国球员从 16 岁到退役的模拟器 | 触发；读取生涯参考，建立循环、状态与位置差异 | 只写球星传记和五道问答 |
| 这是现有足球游戏，第二章不够有选择感 | 触发；读现有实现，定点改分支与反馈 | 重新从观众、平台问起 |
| 不要提问，自行决定，先做完整可玩版 | 触发；注明假设并实施可逆开发 | 停在确认方案；假定允许付费/公开发布 |
| 我只要一份足球游戏策划，不要写代码 | 触发；按范围交策划 | 强制创建完整引擎 |
| 真正赛果不变，但想让不同选择有意义 | 触发；用关系、视角、档案或理解变化承载选择 | 悄悄修改历史赛果 |
| 想让那场真实失利改成获胜 | 触发；明确架空分歧点，再创作分支 | 把改写结果放进事实台账当 verified |
| 给我一个原创门将生涯，最后能导出卡片 | 触发；GK 稳定 id、专属指标、统一 summary | 显示名用于枚举判断；用进球评价门将 |
| 换成明亮漫画风，其他不变 | 触发；修改风格锚点、样片和相关素材 | 重写全部剧情或擅自改变玩法 |
| 没有图片工具，先把原型做出来 | 触发；标注占位，交可运行结构和素材计划 | 声称图片已经生成 |
| 帮我查某场比赛比分 | 不触发这个制作 Skill | 自动开启游戏访谈 |
| 写一篇球星公众号告别文章 | 不触发，除非用户同时要游戏 | 强行生成游戏项目 |

## 开放形式回归

| 输入 | 应有行为 | 应避免 |
| --- | --- | --- |
| 几个人手机扮演业余队成员，在城市找线索解谜，别先选类型 | 自由探索玩家行动、信息关系和城市作用；按需补真人同步、私有线索、路线验证 | 改成单人选择小说加聊天外观 |
| 我想做只靠手指节奏操控门将的游戏，没有剧情 | 围绕输入、时机和扑救反馈做机制样片 | 强制五章、人物插画或结局片段 |
| 还没想清类型，想让足球和我家的旧物发生关系 | 从用户画面或物件经历出发，允许新机制 | 让用户必须选叙事/生涯/混合 |
| 我想做线下主持的球队角色扮演，手机只发秘密信息 | 设计角色权限、信息发送和主持规则，验证保密与协作 | 默认所有玩家共享全部状态 |
| 已有 Unity 项目，只调整局部操作体验 | 读取现有实现，在原引擎验证修改 | 默认重写为 HTML 节点游戏 |

## 检查维度

每案记录是否正确触发、首轮问题数、是否利用已知信息、是否产出可见成果、是否准确陈述工具能力与测试状态、后续修改是否保留用户认可内容。关键失败是失真史实、假装完成制作、丢失已有偏好、重复要求许可或问卷阻塞。
