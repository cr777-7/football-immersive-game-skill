# 视听制作与资源生产

## 先做风格锚点

把用户的参考拆成线条/材质、色板、光线、镜头、人物比例、UI 字体与留白。说明保留哪些特征；不要把参考项目的风格当作唯一标准。

当体验依赖人物和场景插画时，先做人物、场景及其放进真实 UI 的样片，再批量生产。无此需求的玩法改用适合的视觉锚点；机制验证不依赖美术时先做灰盒，不强制先出人物图。没有图像工具时交付可执行提示词和明确占位图，并继续做可玩的结构；不能声称已经生成图片。调用可用生成/编辑工具时遵循其工具约定。

人物锚点表按年代记录：年龄、脸型、发型、肤色、球衣赛季/号码、配饰、典型姿态。真实人物以用户认可参考为准。年龄变化要可识别但不换人。修改已认可图时明确保留项和改动项。

## 画面服务操作

按目标设备确定构图比例，检查实际输出尺寸与宽高比是否一致。背景适配 viewport 后复查裁切；人物脸、球、奖杯和关键动作不要落到 HUD 或对白框下。

对白留白根据实际屏幕、文字量和 UI 位置确定，不机械套用固定比例。证据截图使用 contain/可缩放，不能裁掉关键文字；背景才适合 cover。

选择组件由叙事功能决定：比分板讲清局势，时间线展示跨度，档案提供依据，关系图展示关系，漫画压缩动作，卡片承载记忆。无需每章为了“丰富”强塞新组件。

## 可复用提示词骨架

```text
用途与节点：{背景/人物/关键动作/结局；节点ID}
场景：{年代、地点、天气、具体动作}
人物锚点：{身份、年龄、脸/发型、服装赛季、号码、配饰}
画面重点：{情绪通过什么表情和身体动作表达}
视觉锚点：{用户认可的线条、材质、色板、光照、镜头}
构图：{横竖比例、人物位置、UI留白、裁切安全区域}
连续性：{与哪些图片保持一致，哪些细节要变化}
避免：{本项目实际不希望出现的物体、错年代服装、额外人物等}
标注：{史实插画/原创/架空，图片内是否需要文字}
```

比分、按钮、对白等可变文字优先交给 UI 排版，避免烘焙进背景后无法修改。素材文件用稳定 id，提示词与节点引用可追溯。

## 素材清单

在 assets.json 为每项记录 id、kind、path、status、dimensions、source、rights、prompt、styleVersion、nodeRefs、notes。status 为 placeholder/generated/supplied/ready；rights 未知时写 unknown，不假定可公开再分发。只收集本项目必要素材。

默认按文件引用，构建时再按交付需要压缩/内联。分别测量首屏传输、总资源与单文件包大小；给图片设实际质量预算，音乐单独算。Base64 不等于压缩，单文件也不等于离线可用，检查字体、脚本与远程资源。

## 声音按叙事时点安排

制作声音 cue 表：节点、通道（BGM/AMB/SFX/VOICE）、进入/退出、循环、音量、淡入淡出、授权或占位状态。允许留白，不让每页音效争夺注意。

- 播放按钮的用户手势中触发音频解锁，再做异步加载；不能假设自动播放成功。
- 统一音频管理，静音和页面隐藏影响所有通道，不只影响当前 BGM 引用。
- 打字音使用一条受控循环或限频播放；完成、跳过和离开节点立即停。
- 尊重静音选择，恢复页面不擅自开声；不宣称网页能可靠检测手机系统静音开关。
- 缺音频、播放失败和用户拒绝声音都不能阻塞游戏。

音乐与照片等资源许可在实际使用和发布范围内确认。模拟新闻版面和 AI 生成“历史画面”在体验中有合适标注，不作为史料出处。
