# 验收与交付

## 验收从简报倒推

先列项目实际承诺，再对应验证。下表不是完整游戏类型清单，按实际玩法新增测试。没有广告不测广告，没有生涯不跑赛季模拟。实时玩法验证输入延迟和反馈；真实多人验证两个独立客户端、同步与断线；空间玩法验证路线/定位替代方案和现场可行性。相关测试取决于实际承诺，不能仅测试叙事分支后声称所有机制通过。静态检查、桌面浏览器试玩和真机测试分开记录；未执行写未测，不能用代码推测充当实测。

| 范畴 | 重点检查 |
| --- | --- |
| 需求一致 | 玩家身份、核心动作、历史边界、时长与最终实现一致 |
| 剧情结构 | 所有选项目标存在；起点可达；必需结局可达；没有意外死路 |
| 选择反馈 | 两条路径有承诺的差异；状态更新一次；延迟回响能出现 |
| 史实 | 日期比分奖项有台账；冲突已处理或标注；虚构与史实分清 |
| 文案 | POV/HUD 一致；结局不羞辱；情绪有铺垫；文字不溢出 |
| 美术 | 人物与年代一致；实际裁切不遮脸；档案可读；无缺图 |
| 声音 | 用户手势可播放；静音所有通道；隐藏暂停；拒播不阻塞 |
| 交互 | 快速连点、选项弹窗、自动推进、加载竞态不跳剧情 |
| 状态 | 刷新、继续、重开、旧存档、空历史有明确处理 |
| 适配 | 手机窄屏、长文本、键盘、减弱动画与桌面可操作 |
| 弱网/离线 | 素材缺失有降级；实际交付承诺的离线能力成立 |
| 性能 | 首屏时间与包体实际测量；不把 base64 当压缩 |
| 模拟 | 各位置/速度/年龄边界/转会/退役；多种子统计与不变量 |
| 可选集成 | SDK 不可用、取消、错误、超时；奖励幂等；分享图可导出 |

条件分支需要运行时枚举或测试路径，图检查不能验证条件可满足。使用分数时测试每个阈值上下边界，算出真实最大/最小值；不要只测默认正向路径。

## 试玩方式

先让用户独立体验样片，观察其卡住/误点/失去兴趣的地方。每次只问当前最影响判断的几项：最想继续的一刻、最无意义的选择、最想先改的一处。把“我感觉”记录为反馈，将“无法继续/数字算错”记录为缺陷，优先修复阻塞与错误，再打磨审美。

使用 design/playtest.md 记录版本、设备/浏览器、路径/种子、观察、优先级、改动、复测。确认修复的可观察证据，不靠“已优化体验”。

## 完成交付

交付包包含：
1. 能实际运行的源码及运行说明；有构建步骤时提供依赖清单与锁文件。
2. 发布产物（如用户需要），使用相对路径，注明是否依赖网络。
3. 被实际引用的素材及来源/授权/生成说明，不混入原始凭据和无关缓存。
4. 简报、最新决定、事实台账、素材清单，方便下一轮修改。
5. 测试结果与仍未测试的平台/功能；保留可复现种子和路径。

先从干净副本按说明启动，再打包。若用户要求 GitHub 就绪，补 README、忽略规则、许可说明和必要检查；只有用户要求上传/发布时才执行远端操作。

完成报告给可打开入口、这版实现、如何运行、重要限制。下一轮可直接从“改结尾/换画风/增加转会”开始，无需重填需求。
