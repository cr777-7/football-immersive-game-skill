# 生涯模拟：可解释的规则与有记忆的故事

## 最小可玩循环

创建球员 → 展示当前处境 → 训练/比赛/关系/转会决策 → 结算一个时间单位 → 展示原因与结果 → 保存 → 下一轮 → 退役总结。

先让 3–5 个回合构成一次有取舍的体验，再扩展球队库和事件量。若用户要从少年到退役，增加快进，但以逐赛季结算实现，不简单把产出乘以年数。

## 状态与语义

使用稳定 id，将显示名分离：`positionId: GK` 与 `positionLabel: 门将` 不能混用；俱乐部 id 与赛季联赛归属分开。

建议状态按项目裁剪：
- 身份：姓名、出生年、年龄、位置、国籍、球衣号。
- 能力：技术、速度、体能、心理和位置专属属性；记录当前与巅峰。
- 处境：俱乐部、合同、薪资、出场顺位、健康/伤病风险、士气、声望、适应度。
- 关系：教练信任、队友关系、球迷认同，范围与含义明确。
- 记录：每季俱乐部数据、国家队数据、荣誉、转会/租借历史、总收入。
- 运行：时间、随机种子与 RNG 状态、已发生事件、待完成选择、存档版本。

每项数值写单位、范围、增长来源、衰减条件、影响结果。例如薪资的单位究竟是欧元/年还是万欧元/年，状态越大代表主力还是替补。提示颜色按利弊语义决定，不按正负号统一决定。

## 结算次序

确定本回合有效年数；逐年执行年龄与状态更新、训练和事件、当季比赛、当季荣誉、收入和历史记录，再处理下季转会/升降级等跨季变化。具体顺序可以不同，但必须写清并与文案一致。

转会窗口若发生季前则在该季比赛前处理，不能出现先按原队比赛、再把本季荣誉记到新队。租借同时记录 parentClubId 与 playingClubId，回归条件显式定义。

接近退役上限时只结算剩余年数。快进跨过 30 岁等能力拐点、合同期满、伤愈、租借结束、国家队赛事时，逐年/逐事件检查，不能跳过。达到退役条件后，任何转会、事件和继续按钮都不能再次增加赛季或发薪。

## 随机与平衡

使用可设种子的 RNG，保存 RNG 状态，让相同初态和选择序列可重放。叙事随机数与规则随机数分流，避免多渲染一次页面改变赛果。

事件先按年龄、位置、联赛、关系、已发生历史过滤，再按剩余候选权重抽样。无放回抽取每次重新计算总权重；空池有正常回合兜底。不要让“唯一事件”因读档或重复点击发生两次。

能力、出场、疲劳、伤病、球队实力共同影响赛季结果；只改变伤病条却完全不影响出场的选择是空机制。失败需要可理解原因，避免唯一正确选项和纯随机惩罚。

前锋、后卫、门将各有成就逻辑。门将应看扑救/零封等已实际模拟的指标，不能只是隐藏进球再套用前锋评价。没有模拟的指标不可凭空补入总结。

薪资、身价和收入区别清楚；转会不必永远涨薪。若数值为游戏平衡而简化，明确是模拟设定。不要把能力分简单换成“超过 99% 玩家”；真实百分位需要真实样本及明确口径。

## 叙事响应

事件文本由已结算状态驱动。例如低出场可能是伤病、替补或适应，不统一写“伤病困扰”；留队多年和频繁转会应得到不同告别。关键选择写入记忆，再在关系变化、采访、结局中回收。

结局统一读取 summary 数据，不在页面、分享图和成就系统各算一套。巅峰能力、最终能力、最高联赛、总收入的定义一致。空历史、没有荣誉、零出场都应有自然文案和有限数值。

## 必测不变量

- 相同种子和操作得到相同结果；存档读档不改变下一次抽样。
- 年龄单调增加且不超过规则上限；实际赛季数等于逐年记录数。
- 总数据等于各季之和；俱乐部和国家队统计不重复相加。
- 薪资单位一致，总收入只按实际经过时间计入一次。
- 有限数值，无 NaN/Infinity；空历史有合理初值。
- 出场、进球等非负；位置权重和概率在约定范围。
- 荣誉属于获得时的球队/赛事/赛季；租借归属一致。
- 所有位置、快进速度、退役入口都可结束，结束后不可继续结算。

用固定种子集批量跑完整生涯，统计失败/退役率、主要结局与转会分布。样本量按复杂度选择并记录；可从 100 个种子开始，不把“跑过若干局”冒充平衡已完美。再人工试玩有代表性的极端路径。
